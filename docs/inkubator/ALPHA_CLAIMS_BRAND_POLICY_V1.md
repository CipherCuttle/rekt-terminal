# REKT INKUBATOR — ALPHA CLAIMS / BRAND POLICY V1

**Status:** STAGE-I PREP AUTHORITY  
**Date:** 2026-09-17  
**Parent:** `STAGE_I_ALPHA_REHEARSAL_V1.md`

## 1. Purpose

Prevent product copy, operator communication or Alpha promotion from claiming more affiliation, certainty, security, qualification, payment or review authority than the evidence supports.

Communication invariant:

> **Never claim more certainty than the evidence supports.**

## 2. REKT / Ink identity

Allowed:

- `REKT Inkubator` as the product name;
- `REKT-native` or `built for the REKT / Ink builder community` when describing product positioning;
- factual references to Ink ecosystem compatibility or supported integrations that actually exist.

Forbidden without explicit documentary authority from the relevant organization:

- `official REKT product`;
- `official Ink product`;
- `endorsed by REKT`, `endorsed by Ink`, `approved by`, `partnered with`, or equivalent;
- logos, badges or sponsorship language that imply a formal relationship not actually granted.

If a real sponsorship or official relationship is later granted, the exact scope and wording must be recorded before public use.

## 3. Alpha / readiness language

Allowed during Stage I:

- `closed alpha` only after the owner explicitly authorizes external-human Alpha;
- `rehearsal`, `synthetic rehearsal`, `testnet`, `mock value`, `pre-production`, or `experimental` when accurate;
- precise statements such as `passed the frozen acceptance criteria recorded for this Challenge`.

Forbidden:

- `production ready` as a universal status;
- `battle tested` unless tied to explicit dated evidence;
- `safe`, `secure`, `guaranteed`, `risk-free`, `trustless`, `fully audited`, or `unhackable` as blanket claims;
- implying synthetic tests prove market demand or real-user usability.

Prefer bounded language:

- `validated against <named profile/envelope>`;
- `passed <named test/review>`;
- `known / assumed / unknown`;
- `closed-alpha evidence only`.

## 4. Qualification and winner language

`QUALIFIED` means only:

> the final submission satisfied the frozen mandatory qualification contract under the recorded Test Arena evidence.

It does **not** mean:

- best implementation overall;
- bug-free;
- secure beyond the tested profile;
- officially endorsed;
- guaranteed production fitness.

`WINNER` / `SELECTED` means:

> the organizer selected that entry from the final qualifier set under the frozen selection rules.

Organizer preference must never be described as objective qualification.

## 5. AI / compiler language

Allowed:

- `AI-assisted`; `model-assisted`; `compiler suggestion`; `recommended candidate`;
- explanations that model output is advisory and subject to deterministic validation / explicit human acceptance.

Forbidden:

- `AI verified` when the model merely generated or summarized content;
- representing model output as frozen Challenge authority;
- saying the model `proved`, `certified`, `approved`, or `qualified` a submission unless a separately named deterministic mechanism actually did so.

Core Challenge operation must remain valid when model inference is unavailable.

## 6. Security / review / audit claims

Use only the exact review type that actually occurred.

Allowed examples:

- `independent hostile review returned CLEAN_NO_CRITICAL_HIGH for the reviewed Stage-H range`;
- `exact-head CI/Auth/Postgres gates passed`;
- `H3 closed with an explicit review-gate waiver`;
- `H4 closed with owner-authorized self-review substitution`;
- `H5 closed with an explicit review-transport waiver`.

Forbidden:

- describing H3, H4 or H5 as independently reviewed;
- calling internal CI an external audit;
- claiming the entire product is `audited` from one bounded review;
- implying review proves absence of all vulnerabilities.

## 7. Payment / value language

During Stage-I prep and Closed Alpha, unless later production-value authority is explicitly granted:

Allowed:

- `mock value`;
- `testnet value`;
- `synthetic settlement fact`;
- `no production-money movement`.

Forbidden:

- `paid` / `payout completed` when only synthetic or testnet state exists;
- implying a real prize is escrowed, guaranteed or settled when no authorized production settlement rail exists;
- implying wallet custody/signing/broadcast capability that is not active.

UI copy must make value state visibly distinguishable: `MOCK`, `TESTNET`, or later `PRODUCTION` only under separate authority.

## 8. Sponsorship / community language

Do not imply sponsorship, affiliation or community endorsement from:

- a participant using the product;
- a builder joining a Challenge;
- a project being compatible with Ink/REKT;
- a third party sharing or discussing the product.

A sponsorship claim requires explicit sponsor identity, scope, period and approved wording.

## 9. Correction law

If a public claim is discovered to be materially wrong:

1. stop repeating it;
2. preserve the original evidence/history where relevant;
3. issue a clear correction rather than silently rewriting durable Challenge truth;
4. update product copy/docs to the bounded factual wording;
5. record the correction source when it affects trust, qualification, payment or affiliation.

## 10. Alpha gate

External-human Alpha may not be promoted until the operator can answer, for every public claim:

- what evidence supports it;
- what scope it applies to;
- what it explicitly does **not** mean.
