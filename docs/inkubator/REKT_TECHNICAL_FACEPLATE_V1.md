## 2. MASTER VISUAL REFERENCE

The `instrument-v2` Builder History calibration at `817a310f...` is the **master proportion/detail reference** for production convergence.

Its value is not the PLAYER content itself. Its value is the compositional grammar:

- one pale manufactured chassis;
- large calm planes of unfilled surface;
- a narrow control/navigation rail;
- a dominant active instrument;
- a narrow supporting inspector where needed;
- extreme scale contrast between human headline and machine notation;
- dense micrographics that never become card soup;
- localized dark display wells;
- subtle physical asymmetry and manufacturing detail;
- color used as state/action semantics rather than atmosphere.

If a new surface looks polished but no longer feels related to this calibration with the REKT logo removed, it is noncompliant.

## 3. CORE COMPOSITION LAW

The default REKT page grammar is:

`CHASSIS -> PRINT -> INSTRUMENT WELL -> CONTROL / INSPECTOR`

Not:

`PAGE -> CARD -> CARD -> CARD -> CARD`

### 3.1 Continuous faceplate

The pale chassis is the primary substrate. Functional groups are separated using:

- whitespace;
- thin seams;
- rules;
- hatch bands;
- typography;
- index numbers;
- alignment;
- inset display wells;
- true control boundaries.

Rounded cards are not the default grouping primitive.

A rounded or bordered module is permitted only when it represents a real distinct control, inset instrument, inspector, receipt, dialog or bounded interaction object.

### 3.2 Same hardware, different instrument

COMMAND, PROJECT, WORLD, PLAYER and SHIP must look like **different modes of one machine**, not identical templates and not adjacent brands.

Freeze across surfaces:

- material;
- typography hierarchy;
- rail/control proportions;
- seam and bezel construction;
- micrographic vocabulary;
- line weights;
- state color semantics;
- control grammar;
- motion character.

Allow to differ by surface:

- the central diagram;
- information topology;
- density required by the surface's unique question;
- inspector content;
- chronology / receiver / verifier / artifact / history visualization.

## 4. CANONICAL PROPORTIONS

The master calibration establishes the reference ratios.

### Desktop machine

- outer machine maximum width: approximately `1640px`;
- machine top bar: approximately `68px` high;
- desktop control/navigation rail: approximately `166px` wide at full desktop;
- rail is roughly one-tenth of the machine width, not a dominant sidebar;
- normal workspace horizontal padding: approximately `30px`;
- wide-screen workspace padding may grow to approximately `44px`;
- major headline range: approximately `42–64px` on desktop, rare and dominant;
- technical microcopy: normally `8–10px` mono;
- functional labels/content: normally `12–17px`;
- inspector/title tier: approximately `25–30px` where required.

### Complex instrument split

For surfaces that need a primary instrument plus evidence inspector, start from the F1 relationship:

`PRIMARY INSTRUMENT : INSPECTOR ~= 70–77% : 23–30%`

Reference implementation:

- primary: `minmax(0, 1fr)`;
- inspector: approximately `305px` on standard desktop;
- gap: approximately `26px`;
- wide desktop may grow inspector to approximately `340px` with approximately `36px` gap.

Do not force an inspector onto a surface that does not need one.

### Vertical rhythm

Preferred sequence:

1. compact machine header;
2. generous human identity / mission / object statement;
3. thin calibration/state/control band when needed;
4. dense primary instrument zone;
5. supporting evidence / earned / action strip;
6. quiet footer/imprint.

The active instrument should not consume the entire page merely because it is visually interesting.

### Mobile

Mobile is a sibling composition, not a scaled desktop.

- remove the permanent desktop rail when it becomes spatially expensive;
- use a compact bottom/contextual mode control where product IA permits;
- retain the same type hierarchy and faceplate detail density at readable sizes;
- primary display becomes full-width;
- inspectors fold beneath or into selected rows;
- preserve large calm chassis planes;
- never shrink microcopy below practical legibility to preserve an “instrument” look.

## 5. MATERIAL STACK

### FACEPLATE / CHASSIS

Dominant material:

- warm off-white / pale grey;
- near-black printed graphics;
- faint neutral seams;
- tiny relief only where planes physically separate;
- no glassmorphism;
- no purple wash;
- no generic frosted panels;
- no gradient atmosphere as structural design.

### PRINT

PRINT is a first-class system, not decoration.

Use printed graphics for:

- section numbers;
- mode labels;
- source and destination labels;
- UTC/time-base notation;
- ownership labels;
- small instructions;
- real reference IDs;
- truth-state labels;
- scale/ruler notation;
- input/output labels;
- status strips;
- harmless REKT imprints;
- registration/hatch motifs.

PRINT should feel low-cost in color count and high-cost in alignment and typography.

### DISPLAY WELL

Dark near-black wells are reserved for active instrumentation.

Canonical physical treatment derives from F1:

- approximately `7px` bezel on top/sides;
- approximately `10px` lower lip;
- approximately `8px` outer radius;
- subtle bright upper relief;
- subtle inset dark line;
- restrained inner shadow;
- optional tiny corner fastener;
- optional low-contrast 1px/4px scanline treatment.

This small asymmetry is intentional: a display should read as installed hardware, not a black CSS rectangle.

## 6. COLOR DISCIPLINE

The faceplate is almost monochrome.

### Outside dark displays

Default visible hierarchy:

1. off-white / pale grey chassis;
2. black / graphite print;
3. sparse REKT orange for active selection, intervention or control;
4. semantic color only when needed.

Cyan, violet and acid green should be rare on the pale faceplate.

### Inside dark displays

- cyan = OBSERVED / received / live supported signal;
- violet = REKT identity/context/current locus, and explicit CLAIMED semantics only where Signal Grammar permits;
- orange/amber = action, attention or intervention;
- coral/red = blocked / failed / destructive;
- acid green = PROVEN only;
- cool off-white = primary display text;
- muted grey = unsupported/stale/secondary display notation.

**Green remains sacred.** It may not become generic “good,” online or decorative status.

Color cannot be the only carrier of state.

## 7. TYPOGRAPHIC CONTRAST

The REKT Technical Faceplate depends on **extreme scale contrast**.

### HUMAN layer

Large, heavy grotesk/industrial sans.

Used for:

- mission;
- project identity;
- builder identity;
- artifact identity;
- one dominant page statement.

Large type is rare. It must not become five competing hero headlines.

### MACHINE layer

Small mono technical notation.

Used for:

- indexes;
- timestamps;
- reference IDs;
- source labels;
- truth labels;
- mode labels;
- counts;
- hints;
- coordinates only where meaningful;
- calibration/state copy.

### FUNCTIONAL layer

Readable neutral sans for ordinary explanations, row labels and controls.

Do not set entire pages in mono.

Do not make everything medium-sized. The favorite reference works because `8–10px` machine notation can sit beside `42–64px` human statements without ambiguity.

## 8. MICROGRAPHICS ARE PRIMARY IDENTITY

Micrographics are not polish to add at the end. They are one of the core REKT brand systems.

Canonical primitive family:

1. `PrintedHeader`
2. `MicroLabel`
3. `IndexNumber`
4. `RegistrationMark`
5. `HatchBand`
6. `TruthLamp`
7. `RulerTicks`
8. `ThreadNode`
9. `SourceSocket`
10. `CountReadout`
11. `ProvenanceRow`
12. `DisplayBezel`
13. `Fastener`
14. `StatusStrip`
15. `EventArrow`
16. `RektGlyph`

Additional primitives require a real recurring need; do not grow a decorative icon zoo.

### Micrographic entitlement test

Every micrographic must be one of:

- **DATA** — renders real supported information;
- **CONTROL** — communicates a real action or mode;
- **STATE** — communicates authorized truth/status;
- **STRUCTURE** — seam, ruler, index, registration or manufacturing affordance;
- **IDENTITY** — harmless REKT imprint/personality that cannot be mistaken for telemetry.

If it looks like data but has no supported data source, delete it.

## 9. DENSITY LAW

The system is **detailed but not crowded**.

Use this rhythm:

`CALM PLANE -> DENSE FUNCTIONAL CLUSTER -> CALM PLANE -> ACTIVE DISPLAY`

Do not distribute equal visual noise everywhere.

A high-detail region earns its density by supporting inspection, comparison, chronology, state or action.

A blank region is not unfinished. Negative space is part of the faceplate.

---

## 10. CONTROL LANGUAGE

Controls should feel installed into the faceplate rather than dropped in from a component library.

Preferred treatment:

- compact rectangular switches;
- thin borders;
- sparse filled active states;
- orange current-selection indicator;
- short labels;
- no giant pill buttons as default;
- no floating CTA gradient buttons;
- no decorative knobs/sliders unless they map to an actual continuous value.

A control must look operable without pretending to be literal hardware.

---

## 11. MOTION CHARACTER

Motion combines the technical faceplate with old handheld / segment-display economy.

Default rules:

- static frame must already be excellent;
- low frame count;
- tiny travel distances;
- mechanical state changes;
- reactive movement follows user action;
- event movement follows an authorized projection delta;
- proof ceremony is rare;
- ambient motion is minimal and semantically neutral;
- no constant fake waveform activity;
- no “dashboard breathing” effects;
- reduced motion preserves all meaning.

Character/sprite motion may add personality, but it cannot become a second truth channel.

## 12. SURFACE TRANSLATION

### COMMAND — CONTROL / MISSION INSTRUMENT

Owns: **What should I do now?**

Use:

- one dominant human mission statement on the chassis;
- one purposeful dark thread/gate instrument;
- printed source / gate / NOW / SHIP notation;
- tiny ruler/index/socket graphics around real state;
- one dominant Next Move;
- optional small advisory context.

Do not turn COMMAND into a full backlog or telemetry wall.

### PROJECT — FORENSIC WORKBENCH

Owns: **What is actually happening to this thing I am building?**

Prefer the F1 complex split:

- dominant project/thread/artifact instrument;
- narrow provenance inspector;
- real source/ref/timestamp labels;
- evidence and current locus rendered with the shared micrographic vocabulary.

Do not become COMMAND #2.

### WORLD — RECEIVER / SIGNAL TAPE

Owns: **What useful thing is happening around me that I would otherwise miss?**

Use:

- the same faceplate and display construction;
- receiver/channel language only where supported by public temporal events;
- timestamp/ruler/index notation;
- chronological tape;
- expressive arrival only if it does not imply unsupported spatial relationships.

Hash radar / fake spatial topology remains prohibited.

### PLAYER — DURABLE RECORD

Owns: **What has this builder actually done and earned?**

The F1 Builder History calibration is the strongest direct master reference.

Retain:

- builder identity;
- chronological record;
- selected-record inspector;
- evidence-linked earned state;
- restrained REKT identity detail;
- sequence, not XP/progress score.

### SHIP — VERIFICATION / RECEIPT INSTRUMENT

Owns: **What artifact exists, what was observed, and what was actually accepted?**

Use:

- artifact identity on the chassis;
- dark verification instrument;
- `SUBMITTED -> OBSERVED -> ACCEPTED/PROVEN` visual sequence only when supported;
- verifier readouts;
- evidence/receipt references;
- precise acid-green proof indication only after accepted proof semantics are satisfied.

Verifier PASS alone is not PROVEN.

## 13. REKT PERSONALITY

The faceplate should be technically serious without becoming corporate.

Permitted harmless personality includes compact printed lines such as:

- `SAME DEGENS. HIGHER PURPOSE.`
- `REKT / INKUBATOR / INSTRUMENT SERIES`
- `BUILD SOMETHING THAT REMAINS.`

New joke copy must not masquerade as domain state, instructions, safety information or proof.

Use personality in imprints and labels, not in every module.

---

## 14. CARD / EFFECT KILL CRITERIA

Reject or rework if:

- the page reads as a SaaS card grid;
- every function is boxed independently;
- dark material dominates the whole operational page;
- large purple/cyan gradients create atmosphere without meaning;
- glow substitutes for hierarchy;
- micrographics are random sci-fi decoration;
- fake meters/waveforms imply unsupported activity;
- every surface uses the same internal diagram;
- every surface invents its own bezel, line, typography or spacing system;
- the visual family depends on the REKT logo to feel related;
- mobile becomes a shrunken desktop;
- a reference device is copied literally;
- new visual experiments are created instead of converging existing surfaces.

## 16. VISUAL ACCEPTANCE GATE

A launch-critical surface passes only if:

- it answers its one owned question within roughly one second;
- the page is majority pale faceplate rather than dark dashboard;
- dark wells are purposeful;
- the F1 proportions are visibly recognizable where the surface topology permits;
- micrographics look authored and functional rather than decorative;
- outside-display color remains sparse;
- typography shows strong human-vs-machine scale contrast;
- cards are not the dominant grouping grammar;
- semantic color obeys Signal Grammar;
- all data-like graphics are supported by real state;
- static composition is strong with all motion/effects disabled;
- desktop and mobile are recognizable siblings;
- removing the REKT logo still leaves a recognizable REKT Technical Faceplate family.

Final cross-surface proof must include a desktop + mobile contact sheet for COMMAND / PROJECT / WORLD / PLAYER / SHIP.
